# Чат с LLM (FastAPI + OpenAI)

Простой веб-интерфейс для общения с LLM через официальный клиент `openai`.

## Стек
- Backend: FastAPI + Uvicorn
- Frontend: одиночный HTML-файл с чистым JS (`fetch`)
- HTTP-клиент LLM: библиотека `openai` (chat/completions)

## Быстрый старт

### 1. Создайте окружение и установите зависимости
```
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # Linux/macOS
pip install -r requirements.txt
```

### 2. Настройте ключ API
Скопируйте шаблон в `.env` и впишите реальный ключ:
```
copy .env.example .env
```
Откройте `.env` и задайте как минимум `OPENAI_API_KEY=ваш-реальный-ключ`.
Опционально можно указать модель и базовый URL (например, для кастомного
шлюза/прокси):
```
OPENAI_MODEL=deepseek-v4-flash
OPENAI_BASE_URL=https://gpustack.data.lmru.tech/v1
```

> Ключ нигде не дублируется — он читается только из `.env` на сервере и не
> отправляется на клиент. Файл `.env` исключён из git.

### 3. Запустите сервер
```
uvicorn main:app --reload
```

### 4. Откройте в браузере
```
http://127.0.0.1:8000
```

## Структура проекта
- `main.py` — FastAPI-приложение и эндпоинты
- `config.py` — настройки (pydantic-settings из `.env`)
- `llm.py` — singleton-клиент OpenAI и логика вызова
- `static/index.html` — фронтенд
- `requirements.txt`, `.env.example`, `.gitignore`

## Эндпоинты
- `GET /` — HTML-страница
- `POST /api/chat` — принимает `{messages}` (обязательный массив сообщений)
  и опциональные `{temperature, max_tokens, system}` со значениями по умолчанию,
  возвращает `{"reply": "..."}`
- `POST /api/compare` — принимает `{prompt, temperature?, format_guide?, max_tokens?, stop?}`,
  отправляет один и тот же prompt с ограничениями и без, возвращает оба ответа и их метаданные
- `POST /api/stability` — принимает `{prompt, repeats? (1..20), format_guide?, max_tokens?, stop?}`,
  прогоняет один и тот же запрос с одними и теми же ограничениями N раз и проверяет,
  что формат (JSON-схема) выдерживается в каждом прогоне; возвращает прогоны с флагом
  `valid_json` и сводку `{"summary": {"total", "valid_json", "all_valid"}}`

## Важно
- История чата не хранится на сервере: на каждый запрос клиент присылает актуальный
  массив `messages`.
- Системный промпт захардкожен: модель отвечает как «сеньор-разработчик-гопник».
- Параметры `temperature` (0–2) и `max_tokens` (>0) валидируются на бэкенде;
  если не переданы, используются значения по умолчанию (0.7 и 1024).

## Условие завершения (stop sequence)
В «ограниченном» варианте сравнения вместе со стоп-последовательностью
(по умолчанию `КОНЕЦ`) модель получает инструкцию завершить ответ этим словом:
стоп-секвенция срабатывает только если модель сама её сгенерировала. Ответ
проходить очистку (`llm.clean_content`): срезается хвостовой стоп-токен и
обрамляющие ```` ```json ```` — поэтому «ограниченный» ответ остаётся чистым
валидным JSON, что подтверждается проверкой `valid_json` в `/api/stability`.

## Стабильность формата (детерминированность)
Блок «Стабильность формата» в web-интерфейсе (и эндпоинт `POST /api/stability`)
прогоняет один и тот же prompt N раз (по умолчанию 3, до 20) с одинаковыми
ограничениями. Значения в ответе могут отличаться — это же нейросеть, но
структура (та же JSON-схема) должна выдерживаться в каждом прогоне. Итог:
«Формат выдержан в N из N прогонов».

## Сравнение уровней контроля ответа
Эндпоинт `POST /api/compare` отправляет **один и тот же prompt** на API двумя
запросами, чтобы продемонстрировать разный уровень контроля:

| Параметр          | Без ограничений      | С ограничениями            |
|-------------------|----------------------|----------------------------|
| Явный формат      | нет                  | да (`format_guide`)        |
| Лимит длины       | `default_max_tokens` | `max_tokens` (настраивается) |
| Стоп-последовательн.| нет                | `stop` (настраивается)     |
| finish_reason      | обычно `stop`        | `stop` / `length`          |

Эндпоинт `POST /api/compare` принимает JSON:
```json
{
  "prompt": "Текст запроса",
  "format_guide": "все ответ в JSON ...",
  "max_tokens": 200,
  "stop": ""
}
```
- `format_guide` — явное описание формата ответа (добавляется системным сообщением).
  По умолчанию — универсальная JSON-схема:
  ```json
  { "summary": "краткий тезис", "points": ["пункт 1", "пункт 2"], "action": "следующее действие" }
  ```
- `max_tokens` — ограничение длины ответа;
- `stop` — условие завершения (stop-последовательность, необязательно для JSON).

Ответ содержит оба варианта и их метаданные:
```json
{
  "prompt": "...",
  "unconstrained": {"content": "...", "finish_reason": "stop", "completion_tokens": 123, ...},
  "constrained": {"content": "...", "finish_reason": "stop", "completion_tokens": 31, ...}
}
```
В web-интерфейсе блок «Сравнение: свободный vs ограниченный ответ» показывает
оба ответа рядом с причинами завершения и расходом токенов, что наглядно
иллюстрирует влияние контроля на результат.
